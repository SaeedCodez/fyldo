# Changelog

All notable changes to Fyldo are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows [Semantic Versioning](https://semver.org/) (inside a major version the public API only grows; see [docs/ARCHITECTURE.md §6](docs/ARCHITECTURE.md#6-coexistence-design)).

## [Unreleased]

### Added

- **Page links**: `add_page( $id, [ 'links' => [ [ 'label', 'url', 'icon', 'external' ] ] ] )` gives a page buttons of its own in its Page Header (Figma's Page Header actions), such as the page's own help page. They come before the instance's `header` links and show in both layouts, since they belong to the page. A custom page gets them as `page.links`, ready for `ui.PageHeader`'s `links`. A link without `label` or `url`, a `placement` or an unknown key is a config error. The client config's pages gain `links`.

### Changed (API freeze: PHP)

Before 1.0, so that nothing is frozen by accident. After 1.0 the public API only grows inside 1.x.

- **Public API**: only `Fyldo::create`, `instance`, `instances`, `icon`, `is_icon`; `Instance::add_group`, `add_page`, `add_form`, `get`, `all`, `update`, `reset`, `delete_data`, `admin_notice`, `slug`; `Support\Dates::to_site`, `range_to_site`, `time_in_range`; `Schema\ConfigException` and `Bootstrap\Loader` are the 1.x contract (list in [docs/ARCHITECTURE.md §3.2](docs/ARCHITECTURE.md)). Every other class and every other public method is now marked `@internal` and may change in any release. `FileField`, `ImageField`, `PostField`, `TermField` and `UserField` are `final`; `Dates::now()` is private.
- **Page filters renamed** (breaking, no alias): `fyldo/{slug}/sanitize/{page}` is now `fyldo/{slug}/page/{page}/sanitize` and `fyldo/{slug}/validate/{page}` is `fyldo/{slug}/page/{page}/validate`, like the form filters (`…/form/{form}/sanitize|validate|saved`). Same arguments.
- **Option names are unique**: `add_page()` rejects (`_doing_it_wrong`, page skipped) an `option_name` that another registered page of any instance already uses, or that is an instance's `{slug}__fyldo`. Two pages on one option used to overwrite each other's data.
- **`min` / `max` / `step` are field keys**: `number` takes `min`, `max`, `step`; `multi_select`, `checkbox_group` and `post` / `term` / `user` with `multiple` take `min`, `max` (counts), as `slider`, the dates and `group` already do. `validate.min|max|step` is still accepted for `number` and the lists. The same key in both places is a `ConfigException`.
- **`Instance::update()` and `reset()` return what `all()` returns**: `values` is the page's values as `all()` reads them (a password as stored, not hidden for the browser), the result has no `media` key, and the unknown-page result has the same shape.
- **Registration checks**: `add_group()` needs an id that is URL-safe like a page id, not yet used, and a label; a page whose `group` is not registered when the screens are registered (`admin_menu`) is reported with `_doing_it_wrong` and shows ungrouped; an unknown key in an instance's `links` or `menu` is a `ConfigException`; link URLs go through `esc_url_raw()` (one it rejects is a `ConfigException`); a field's `badge` must be a string or an int.
- **Docs**: the empty value of every field type, the reserved form record key `new`, the methods of the record routes, that the client config and the `fyldo/{slug}/config` filter are internal, that `Fyldo::create()` throws while other registration errors are `_doing_it_wrong`, that a page `capability` only narrows the instance's, that `upgraded` fires inside `add_page()`; complete hook lists; `multiselect` is `multi_select`; the `reset` hook gets `$page_id, $stored_before`; default layouts; the `code` rule; the 512 KB body cap is fixed; no more `show_if`.

## [1.0.0-beta.6] - 2026-10-20

### Added

- **Conditional fields** (`dependency`, Codestar style): a field, a notice, a group's sub-field or a whole section shows only while conditions on other fields of the page hold, live as the values change: `'dependency' => [ 'cache', '==', true ]`, or a list of conditions (all must hold; `'relation' => 'or'`: one). Operators `==` `!=` `>` `>=` `<` `<=` `any` `not-any` `contains` `not-contains` `empty` `not-empty`. Hiding cascades (a condition on a hidden field never holds). A hidden field is neither checked nor saved, in the browser and on the server, so what is stored stays. PHP refuses unknown ids, password fields, self-references and circles. `useForm` gains `visible(path)`. Shared cases in `tests/fixtures/dependency-cases.json` (PHPUnit + Vitest). The demo's General page shows a coming-soon message only in maintenance mode. Decision O22.
- **Custom pages**: `add_page( $id, [ 'type' => 'custom', 'module' => …, 'style' => …, 'props' => … ] )` puts a page in Fyldo's navigation whose content the plugin draws with its own ES module, inside Fyldo's content column. The module's default export gets the SDK `{ version: 1, React, ui, Form }` (custom fields now get the same object; `ui` grew from 8 components to every public one) and its component gets `page`, `path` (the route below the page: `#/stories/42` → `['42']`), `navigate` (through the unsaved-changes guard), `request` (the plugin's own REST routes with the WordPress nonce, PUT/PATCH/DELETE sent as POST + override), `toast`, `setDirty` and `headingRef`. For screens that are not settings (record lists, editors, dashboards) without Fyldo growing a feature per screen: decision O19, [docs/custom-pages.md](docs/custom-pages.md).
- **Forms**: `add_form( $id, [ 'sections' => …, 'load' => …, 'save' => … ] )`: a field schema whose records the plugin stores (its own table, a post type…). Fyldo sanitizes and validates exactly as on a settings page (a new record is checked whole), answers 422 and 409, and `<Form form record onSaved>` draws the cards, the Save Bar and the conflict notice. REST `GET|PATCH …/forms/{form}/records/{key}` (`new` = a new record) and the relation search route; hooks `form/{id}/sanitize`, `form/{id}/validate`, `form/{id}/saved`. The client config gains `forms` and `rest.base`; pages carry `type`.
- **Components** (Figma, design pack, code, pixel tests): **Item Card** and **Add Item Card** (a record in a grid: media slot, status and flag badges, title and meta, tags, two footer details, actions; the whole card opens the record), **Pagination**, **Stat Card** (value with a delta whose colour follows its tone), and a **Content** slot in **Modal** (`children`).
- **Theme**: `Fyldo::create( $slug, [ 'theme' => [ 'brand' => [ 600 => '#ff6b4a', … ], 'neutral' => [ … ] ] ] )` gives a plugin's screen its own colours. Every semantic colour (buttons, toggles, focus, links, text, borders, backgrounds, the dialog scrim) now points at a step of the new **Theme** layer (Figma's Theme collection: `brand/50`–`950` and 15 `neutral` steps). The theme sets those steps as custom properties on the instance's root, so fields, components, popovers, dialogs and custom pages follow it and other instances do not. Status colours are not themeable. Unknown steps and non-hex values are config errors. The input focus shadow follows `focus/border` (it was a fixed violet). The demo carries the Pelk mode as `Demo::SAMPLE_THEME` (filter `fyldo/fyldo-demo/theme`). [docs/theming.md](docs/theming.md).
- **SDK field controls**: `ui` gains the controls of Fyldo's own fields, for an editor a plugin draws itself: `ColorPicker`, `DatePicker`, `TimePicker`, `DateRangePicker`, `MediaPicker` and `GroupItem`. They write in the screen's language unless given `locale`, and work outside a Setting Row too (the Date Field then links its other-calendar line itself; the media control is named by its label). `MediaPicker` reports a change as `onValueChange( id, item )` (was `onSelect` / `onRemove`) and, without `media`, looks the attachment up by its ID through `wp.media`. Custom pages and custom fields take `'media' => true` to load the media library on the screen. [docs/custom-pages.md](docs/custom-pages.md#field-controls).
- **`useForm`** (SDK): a record form whose page draws the fields itself (fields that depend on each other, a list it manages, a live preview), on the same engine as `Form`: load, the checks, whole-record save with 422 and 409, the unsaved-changes guard, and `Frame` for the notices, the Save Bar and Ctrl/⌘+S. `field(id)` gives a control its props by field type; `set`, `error`, `errorCount`, `validate`, `save`, `discard`, `invalidSaves`. `Form` now runs on the same engine. Decision O21.
- **SDK**: `ui.GroupList`, Figma "Group" without a schema, for the items a custom page keeps itself (slides, sections): the same list the `group` field draws (drag and keyboard reordering with announcements, Add, Duplicate, Remove with Undo, `min` / `max`, the empty state), each item a Group Item with its title, summary, tile, status, inactive look and error count from callbacks. The `group` field is now drawn with it (one implementation). `ui.ChoiceCards` is public too.
- **Media**: a video's or an audio file's length (`duration`, seconds) in the attachment the `image` and `file` fields describe (PHP from the attachment metadata, the browser from `wp.media`), for players and previews.
- **Fields**: `code` (Figma Code Editor, exported to the design pack with its syntax colours): line numbers, syntax colours for CSS, HTML and JSON, the language and a copy button in a toolbar, always left to right. A real textarea under a coloured copy, so typing, undo and screen readers are the browser's; Tab indents, Shift+Tab outdents, Escape then Tab leaves, Enter keeps the indentation. Config `language`, `rows`, `toolbar`, `line_numbers`. The code is kept as typed (HTML goes through `wp_kses_post` without `unfiltered_html`). New implied rule `code`: JSON must parse, CSS may hold no markup (WordPress's check), its message keyed by line (`<field>.<line>`, "Line 3: …", the line number and its values in red); `validate_cb` may answer by line. `ui.CodeEditor` in the SDK. The demo's Content page has a Code tab. The pack exporter now records the colour runs of multi-colour text (`segments`).
- **Custom fields, `watch`**: a custom field names other fields of its page (`'watch' => [ 'brand_color', 'theme' ]`) and its module gets their current values as `values`, unsaved edits included, as they change: a live preview of the page's settings. PHP checks the ids (same page, not a password field, not itself). The demo's "Opening hours" page gains a preview of how the hours read on the site.
- **Custom fields**: `'module' => false` in a form whose page draws the value (refused on a settings page); `validate_cb` may answer with messages by path inside the value (`array( '2.link' => '…' )` → `slides.2.link`), and a stored value with such messages is kept rather than reset.
- **Group Item status** (Figma, design pack, code): a `Status` badge after the title ("Scheduled", "Ended": what holds for an item without opening it) and a `State=Inactive` whose preview, title and summary fade (an item that is kept but not in effect). In code, `GroupItem`'s `status` (`[{ label, tone, icon }]`, the labels also describe the item's button) and `inactive`. Drawn for Pelk's story slides.
- **TypeScript types for the module SDK**: `assets/dist/fyldo-sdk.d.ts` ships in the release (ZIP, drop-in folder, Composer) with the types of what a custom field's or a custom page's default export receives and returns: `FyldoSdk` (`React`, every `ui` component with its props, `Form`, `useForm`), `CustomFieldExport` / `CustomFieldProps` / `CustomFieldDefinition`, `CustomPageExport` / `CustomPageProps` / `CustomPageDefinition` and `JsonValue`. One self-contained file, generated from the source by `npm run build` (`npm run types`): its only import is `react`, for types (`@types/react` 19 in the plugin). Point `tsconfig` `paths` at it and bundle TSX with esbuild (`--format=esm --bundle --jsx=transform --external:react`): [docs/custom-fields.md](docs/custom-fields.md#typescript).
- **`useForm`, `field(id, kind)`**: the props of one kind of control, typed, so a TypeScript page spreads them as they are (`<ui.Input {...form.field('title', 'text')} />`): `text`, `number`, `list`, `range`, `toggle` and `media`, each value in its control's type (`''` for a text value that is not a string, `[]` for a list…). `field(id)` is unchanged. A kind that does not match the field's type is reported in the console. [docs/custom-pages.md](docs/custom-pages.md#typescript).
- **Demo**: an "Announcements" custom page (Content group): stat cards, status tabs with counts, search, sort, cards, paging, duplicate, a delete dialog with an option, and an editor; the records live in the demo's own database table.

- **Custom fields in a group, `watch`**: a custom sub-field names other sub-fields of its own item (`'watch' => [ 'stories', 'size' ]`) and its module gets that item's current values as `values`, unsaved edits and sub-field defaults included, as they change (a `mount` module through `update`): a live preview inside each item. PHP checks the ids against the item's sub-fields (not the page's fields, not a password field, not itself). Before this, a group's custom field watched the page's fields.
- **SDK**: `ui.IconPicker`, the control the `icon` field draws (Figma Icon Picker and its modal), for an editor a custom page draws itself: the value is an Iconsax name in kebab case, `onValueChange`, `icons` to offer only some names, `size`, `placeholder`, `disabled`, `onBlur` and the aria props. It writes in the screen's language unless given `locale`, and binds as `form.field( id, 'text' )`. Typed in `assets/dist/fyldo-sdk.d.ts`. [docs/custom-pages.md](docs/custom-pages.md#field-controls).
- **Icons outside Fyldo**: `Fyldo::icon( $name, [ 'size', 'class', 'label' ] )` gives one Iconsax icon's `<svg>` markup on the server (24×24 viewBox, `currentColor`, a fixed set of elements and attributes in kebab case, no script), read from that icon's module only and kept for the request, so a site's front end gets exactly the icons it shows; `Fyldo::is_icon( $name )` checks a name. Only names from Fyldo's list (`Support\IconNames`, generated by `npm run icons`) are read. The SDK's `iconSvg( name, options )` gives the same markup in the browser for a module that draws outside React.

### Changed

- **The `icon` field refuses unknown names on the server**: without `icons`, a saved name must be an Iconsax icon Fyldo has (it used to accept any well-formed name), and a stored unknown name reads as the field's default.
- **`Instance::update()` no longer checks what the current user may read**: a `post`, `term`, `user`, `image` or `file` value (on its own or in a group's sub-field) only has to exist and fit the field, as when a value is read. The caller is the plugin's own code, and a save from cron or WP-CLI (no user) used to drop every item. Saves through the REST API still drop the items the user may not read. A plugin that passes values from a request to `update()` checks them itself (`current_user_can( 'read_post', $id )`).
- **Design**: the info tone (Blue Badge and Notice, the Setting Row badge, anything on `status/info/*`) uses the blue scale again instead of the brand violet: bg `blue/100`, border `blue/400`, subtle `blue/300`, solid `blue/700`, text `blue/800`. Synced from Figma with the rest of the design pack.

### Fixed

- **A settings page shown again re-reads its values.** The app kept every page's values and revision for the whole visit, so an option changed outside the page's own save (a form record's `save` callback, another page's save hook) showed its old values, and the next save was refused with a 409 ("changed somewhere else"). Now a settings page with no unsaved edits re-reads what is stored (`GET …/pages/{page}`) each time it is shown, except the page the screen opened on; a field typed into while the read runs keeps its edit. A page with unsaved edits is left as it is, and its save still reports a conflict.
- **Group**: a stored group read its sub-fields as if they were being saved, so a `post`, `term` or `user` sub-field checked whether the current user may read each item: a logged-out visitor (`Instance::all()` on the front end) lost every item of a post type that is not public. Each sub-field is now read through its own `stored_value()`, like a field on its own; saving still checks the user.

## [1.0.0-beta.5] - 2026-10-17

### Added

- **Fields**: `date_range`, `time_range` and `datetime_range` (Figma Date Range Field), built on the single date and time pickers: two inputs, start → end, each opening the single picker's own panel and setting only its end (no range calendar). The value is one array `array( 'start' => …, 'end' => … )`, each end in the single type's stored format (a datetime in UTC); empty is both `''`. Config: the single type's `calendar`, `min`, `max`, `step` and `placeholder` for both ends, plus `start_placeholder` / `end_placeholder`. A date or datetime end opens on the start's month with the days before the start disabled; moving the start past the end clears the end. A time range may cross midnight (22:00 → 06:00 = 8 hours, "ends the next day"). Under the inputs, the duration once both ends are set ("Duration: 7 days", "Duration: 6 days, 9 hours and 30 minutes"; a datetime range counts real time across a daylight-saving change). The server re-validates the pair on every save (each end's format, `min`, `max`, `step`; both ends or neither; the order); the implied rule gains `range`. New helpers `Support\Dates::range_to_site()` and `Dates::time_in_range()`. Layout default `stacked`. The demo's "Dates and times" page has a "Ranges" section and a date range in its group.

- **Fields**: `date`, `time` and `datetime` (Figma Date Field, Calendar Cell, Calendar Panel and Time Panel). Dates show in the **Jalali (Shamsi) or the Gregorian calendar**: `calendar` is `auto` (Jalali on a site whose locale starts with `fa`, else Gregorian, with a switch in the panel), `jalali` or `gregorian`; the switch changes only the view. Under a filled field the same value is shown in the other calendar. The panel has Days, Months and Years views, Today and Clear, the WAI-ARIA date picker keyboard (arrows, Page Up / Down, Home / End, Enter, Escape), Persian numerals and month names, Saturday weeks in Jalali and the site's "Week starts on" in Gregorian. A time is typed as HH:MM (Persian digits too) or picked from hour and minute columns; a datetime has the columns beside the calendar. **What is saved is always Gregorian**: `Y-m-d`, `H:i` (24-hour) and, for a datetime, `Y-m-d H:i:s` in UTC (shown and picked in the site's time zone). `min` / `max` take a stored-format value or `today` / `now`; `step` is minutes. The server checks every value again (strict format, a real day, 00:00–23:59, `min`, `max`, the step) and never trusts the browser's conversion; the time zone always comes from WordPress. `Fyldo\V1\Support\Dates::to_site( $utc )` reads a stored datetime in the site's time zone. The panels are a lazily loaded chunk. The demo has a "Dates and times" page (also inside a group). The client config gains `dates` (`timezone`, `startOfWeek`, `calendar`).

## [1.0.0-beta.4] - 2026-10-13

### Added

- **Fields**: `post`, `term` and `user`, a searchable select whose options are the site's posts (any post type), terms (any taxonomy) or users, loaded from the server while the user types (Figma Select Menu `Type=Search` and the new Menu Message row for searching, no results and errors). Name the source with `post_type` / `post_status`, `taxonomy` or `role`; `multiple` turns it into a Multi Select whose tags keep the pick order. The value is the ID (`0` = none) or a list of IDs; only items the current user may read are offered and saved, and deleted ones drop out when the value is read. `query_args` narrows the search; `min` / `max` count the items. A new REST route, `GET …/pages/{page}/fields/{field}/items`, serves the results (20 a page); the saved items' titles travel with the page's `media`. Works inside a `group`, and a group's `item_title` may name such a sub-field: each item is then named after the post, term or user chosen in it. The demo has a "Links" page with every variant.
- **Fields**: `custom`, a field whose control you draw yourself, in React or plain JavaScript. `module` is the URL of an ES module; Fyldo imports it before the first render and calls its default export with Fyldo's own React and a few of its components (`Button`, `Checkbox`, `Icon`, `Input`, `NumberInput`, `Select`, `Textarea`, `Toggle`), so the field matches the others and no second React is loaded. The module returns a `Component` (or a plain-DOM `mount`) and an optional `validate` for instant feedback. `props` reach the module as-is and `style` enqueues a stylesheet. The value is any JSON value, its text cleaned like a textarea's unless you add `sanitize_cb`; `validate_cb` decides on the server. It works inside a `group`, and a module that fails to load or crashes stays inside its own row. Nothing is written to `window`. See [docs/custom-fields.md](docs/custom-fields.md); the demo has an "Opening hours" page with two selects saved as one value.
- **Fields**: `default_before` keeps the defaults a site already had when a release changes them. List the earlier defaults by the version that replaced them (`'default' => 30, 'default_before' => [ '2.0.0' => 10, '3.0.0' => 20 ]`); when the instance `version` moves forward, Fyldo stores, for each field nobody saved, the default it had in the version the site came from. Saved values are never touched and new installs get today's default. Fyldo now records the version each page last ran in one autoloaded option, `{slug}__fyldo` (only when the instance has a `version`), and fires `fyldo/{slug}/upgraded( $page_id, $from, $to )`. See [docs/default-history.md](docs/default-history.md).
- **Uninstall**: `Instance::delete_data()`, documented since the architecture draft but missing until now. Call it from your plugin's `uninstall.php` after registering the instance and its pages: it deletes every registered page's option and `{slug}__fyldo`, and fires no hooks.
- **Fields**: `group`, a list of items that share the same sub-fields (Figma "Group" and "Group Item"), e.g. header buttons with a label, an icon and a link. The value is a list of arrays keyed by sub-field id. A fixed group keeps the items of its `default`; `sortable` adds drag handles (and keyboard moving: Space, the arrow keys, Escape), `addable` adds Add, Duplicate and Remove with Undo, limited by `min` / `max`. Items are collapsible cards named by `item_title`, with an optional `item_icon` preview tile. Sub-fields validate as on their own; their errors are keyed `<group>.<index>.<sub-field>` and a failed save opens the first item with an error. Sub-fields cannot be groups, media or password fields.

### Changed

- **Design (redesign pass)**: a brand colour and softer neutrals. Primary is `#6e62fe` (buttons, the active navigation item, toggles and checked controls, focus, links, info tones); grays, borders, shadows and the page background are tinted toward `#f6f7fc` instead of pure gray/black; dividers between settings are lighter (`border/subtle`).
- **Design**: bigger controls and a wider settings column. Buttons, inputs and selects are 36 / 44 / 52 px (were 32 / 40 / 48), toggles, checkboxes, radios, tags and sliders are larger, navigation items are 44 px with a solid primary active state, the sidebar header is 76 px with the version at the far end, tabs are 56 px, the content column is 960 px (was 800), and the modal, toast and empty state are wider. Corner radii are unchanged.
- **Sidebar**: the version number moved from the header (next to the logo, where long versions were cut off) to a "Version 1.0" line at the bottom of the sidebar.
- **Scrolling**: on desktop the page no longer scrolls with the WordPress window scrollbar; the content area scrolls inside Fyldo's shell with its own slim, rounded scrollbar (the sidebar and top navigation stay in place). At 782px and below the document scrolls as before.
- **Motion**: every hover, focus and selection change uses one quick, soft 150 ms transition, and pages (and the cards of a tab) fade in over 150 ms when you navigate. Both are off under `prefers-reduced-motion`.
- **Design**: a focused field's halo is a 0.5 px ring in the border colour (was a 3 px, 18 % tint), so the border looks thicker while you type. Sidebar items turn white on hover. Setting Row controls are 400 px wide (the Textarea 448).
- **Accessibility checks**: the contrast test is less strict than WCAG AA (text 4:1, UI 2.5:1; decision O17). White text on the primary fill is 4.34:1.
- **Saving**: a failed save says why. Separate Save Bar messages for an expired login, a missing permission (403), a request that is too large (413) and a server error (5xx, a PHP fatal or a proxy's error page); a network failure keeps its message. The edits always stay on the page, and the server's details go to the console.
- **Saving**: an expired nonce no longer breaks a save. When WordPress or Fyldo refuses a request because a nonce has expired (a tab left open overnight, or a new login), the browser fetches fresh nonces from a new admin-ajax action, `fyldo_{slug}_nonces` (logged-in users only, like core's `rest-nonce`; it grants nothing, every REST request still checks the capability), and sends the request once more. If the user is logged out, the message says to log in again. The client config's `rest` gains `refresh` (that URL).

### Fixed

- **Admin screen**: nothing but Fyldo below the admin bar. WordPress admin notices (core's update nag, other plugins' notices) are no longer printed on a Fyldo screen, and what still lands above the app (notices added by JavaScript, settings errors, the Screen Options and Help tabs, another plugin's banner) is hidden. They pushed the full-height shell down and cut off its bottom. Other admin screens are unchanged; your own messages go through `Instance::admin_notice()`.
- **Fields**: `image` and `file` values read on the front end. A stored attachment ID was checked against `current_user_can( 'read_post' )` on every read, and logged-out visitors (no `read` capability) always got the default, `0`, instead of the saved attachment. Reading a stored value now only checks that the attachment still exists and fits the field; the permission check stays where it belongs, on save and in the admin preview.
- **Admin screen**: a crash while rendering no longer leaves an empty screen. A top-level error boundary shows an error notice with a "Reload page" button (saved settings are untouched) and logs the error to the console. A custom field's crash still stays inside its own row.

## [1.0.0-beta.3] - 2026-10-02

### Changed

- **Fields**: single-line and list fields now default to the `field` layout (control beside the label); set `layout => 'stacked'` for the old look. `choice` stays `stacked`, `toggle` and `checkbox` stay `inline`.
- **Design**: text-field borders are softer (`border/input` is `gray/500`, hover `gray/700`), following the refreshed design. The resting border is 1.66:1 on white, below WCAG 1.4.11 (3:1); this is a recorded exception (decision O16), hover, focus and error borders still pass.
- **Setting Row**: a new `field` layout (title and description on the start side, a 320px control on the end, 360px for wide controls) and the matching Section Card.

### Added

- **Fields**: the `types` of `file` and `image` takes extensions or WordPress type groups such as `'image'` and `'document'` (`wp_get_ext_types()`), e.g. `array( 'document', 'archive', 'image' )`. A group expands to its extensions; the browser still receives the plain extension list. A `file` field accepts every type WordPress allows, images included, when `types` is not set; an `image` field takes only the `image` group or image extensions.
- **Fields**: `image` (Upload Image) and `file` (Select File): one attachment from the WordPress media library, chosen in the native `wp.media` modal (single selection, filtered to the allowed types, the current attachment preselected; Fyldo has no uploader). The stored value is the **attachment ID** (`0` = none); read it with `wp_get_attachment_image_url( (int) $value, 'full' )` / `wp_get_attachment_url( (int) $value )`. `types` (extensions, mapped with `wp_get_mime_types()`) and `max_size` (bytes or `'2MB'`) are checked in the browser and again on the server (the attachment must exist, be readable, be an image for `image`, match `types` and fit `max_size`); a wrong choice shows the field's error and does not change the value. The page payload and the save response carry a `media` object (name, size, type, dimensions, thumbnail) beside the values, so the preview is right after load and after saving. `wp_enqueue_media()` runs only on a Fyldo screen that has one of these fields. Empty and filled share one height; removing only clears the value. New implied `media` rule (attachment ID); Persian numerals and unit names.
- **Fields**: `icon` (an Icon Picker: a preview tile and the icon name that open a modal with a search box and a grid of every Iconsax Linear icon). The value is the kebab-case name (`setting-2`); `default`, `icons` (a list of names that limits the picker and the server-side check) and `validate.required` are supported. The modal and the icon names load on first use, so the main script stays small; each tile's icon loads when it scrolls into view. The change applies only on "Select icon".
- **Fields**: `choice` (a Choice Card Group: one of a few selectable cards, each with an optional image and description; `content` `auto` | `image` | `text`, `columns` 2 | 3 | 4, option `image` URLs are sanitized). Single choice, validated like `radio` (required, one of the enabled options), mirrored in RTL, two columns at most up to 782px and one up to 480px.
- **Fields**: `color` (a Color Picker: swatch and hex value that open a panel with a saturation/brightness area, a hue strip, a hex box and presets). The value is lower-case `#rrggbb`; `default`, `presets` (a list of hex colours, or `false`) and `validate.required` are supported, and the new implied `color` rule runs in PHP and in the browser. The panel is loaded on first use, so the main script stays small.
- **Fields**: `segmented` (a Segmented Control: one of 2–5 short options) and `slider` (a number in a range with `min`, `max` and `step`, shown with its value). Both go through the normal sanitize, validate and save pipeline and mirror in RTL.

## [1.0.0-beta.1] - 2026-09-30

First public beta. The API is feature-complete for 1.0 but not yet frozen: expect small changes before `1.0.0`.

### Added

- **PHP API** (`Fyldo\V1`, PHP 7.4+): declare pages → sections → fields with `Fyldo::create()`, `add_group()`, `add_page()`; read and write with `get()`, `all()`, `update()`, `reset()`; strict registration-time validation with actionable `_doing_it_wrong` messages.
- **Fields**: `text`, `url`, `email`, `password` (write-only), `number`, `textarea` (with counter), `toggle`, `checkbox`, `checkbox_group`, `radio`, `select`, `multi_select`, and the display-only `notice`. Declarative `validate` rules shared by PHP and the browser (one fixture tests both), plus `sanitize_cb` and `validate_cb`.
- **Admin UI**: React 19 + Base UI + Tailwind v4, built from the Figma design pack. English (LTR) and Persian (RTL). Sidebar or Top Navigation, groups, tabs, badges, header and footer links, client-side routing with real links.
- **Saving**: REST-backed sanitize, validate and save with nonce, capability and optimistic-concurrency (409) checks; `global` (Save Bar) and `section` (card footers) save modes; an unsaved-changes guard; Ctrl/⌘+S.
- **Feedback**: toasts, tooltips, notices (`Instance::admin_notice()`), empty states, confirmation modals and a **danger zone** section with a server-checked typed confirmation for resetting a page.
- **Branding**: per-instance `title` and `logo` (Iconsax name or image URL).
- **Coexistence**: any number of copies at any version share one `Fyldo\V1` loader; the highest eligible version wins. Every runtime identifier derives from the instance slug. Strauss-compatible for full isolation.
- **Accessibility**: WCAG 2.2 AA checks (axe) on every component and both layouts, skip link, keyboard walkthrough, `prefers-reduced-motion`.
- **Distribution**: a standalone plugin ZIP (`fyldo.zip`), a drop-in folder and a Composer package, all with prebuilt assets (no Node needed). `npm run release` and a tag-driven GitHub Actions release workflow.

### Not yet

WordPress version matrix, multisite, forced-colors styling and a manual screen-reader pass are planned after 1.0. Fyldo is not published on wordpress.org.
